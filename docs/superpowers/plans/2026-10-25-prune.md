# /prune Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pruning pass by Claude, the direct connection. It shrinks the board without losing a decision. It runs on `/prune`, and automatically between rounds once the board is big.

**Architecture:**
- `lib/prune.mjs` holds the pure rules: the board's size, the law guard and credit-keeping. It also holds a `Pruner` that runs one pass: it saves a version, runs a fresh `claude -p` with the whole board on stdin, and posts a summary.
- The store enforces the guard and keeps credit while `store.pruning` is set.
- `ColabRun` decides when a pass runs. A manual pass runs now when idle, or after the current round during a run; an automatic pass runs between rounds when the size threshold is crossed. `ColabRun` owns Stop for it.
- `Room` routes `/prune`.

**Tech Stack:** Node 18+ ESM with no runtime dependencies, server tests use `node --test`; Svelte 5 + Vite page, tests use vitest.

**Spec:** `docs/superpowers/specs/2026-10-25-prune-design.md`

## Global Constraints

- **Threshold:** `PRUNE_THRESHOLD = 45_000` characters of the `view_board` JSON. Regrowth before the next automatic pass: `PRUNE_REGROW = 10_000`. Both are named exports of `lib/prune.mjs`.
- **Law.** During a pass, the pruner may never:
  - change the label or text of a plain bullet (`check: 'none'`), or delete one;
  - create a plain bullet, or set `check: 'none'` on an entry;
  - touch a struck-through entry (`ruledOut: true`);
  - delete or `bringBack` a ruled-out record;
  - change the title, notes, props or status of an accepted card, or delete one;
  - change or delete a connection between two accepted cards;
  - post to the chat;
  - delete a picture.
- **Moves are allowed.** Plain bullets may move between groups (`moveEntry`), and accepted cards may move (x/y only, or `tidy`).
- **Credit.** Edits keep the original `author` and `updatedBy`. Anything the pass creates gets `claudeAdded: false`.
- **Version name:** `Before prune YYYY-MM-DD HH:MM` in local time, saved with `auto: true`.
- **Time limit:** a pass gets `colab.turnLimit` (the board's Turn timeout), not the 10-minute chat limit.
- **No binary:** `/prune` is refused with `/prune needs the claude command.` An automatic pass is skipped with the chat note `Skipped pruning: it needs the claude command.`
- **The command hint** becomes `/chat N (or /c N) · /start · /stop · /prune`, in `lib/commands.mjs` and in `web/src/components/Chat.svelte`. The page keeps its trailing ` · ↑ for earlier messages`.
- **Prompt delivery:** every `claude -p` prompt goes on stdin, never as a command-line argument (Linux caps one argument at 128 KiB).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A board already over the limit** (ninjas, about 87K): a pass must still start and get the whole board. This is pinned in Task 3 (stdin) and Task 4 (the prompt carries the full view).
2. **Stop during a pass that is waiting for the binary,** which is busy answering chat: Stop must cut the wait, not hang. Pinned in Task 5.
3. **A pass that fails or is cut short** must still clear `store.pruning`, or every later Claude op would be guarded. Pinned in Task 4.
4. **Chat sent while an idle pass runs** is answered after the pass, not lost. Cards wait, and the binary queues. Pinned in Task 5.
5. **An automatic pass that leaves the board over the threshold** must not repeat every round. Pinned in Task 5.

### Task 4: The Pruner: one pass from start to summary

**Files:**
- Modify: `lib/prune.mjs` (add `Pruner`, `PRUNE_SYSTEM_PROMPT`, `prunePrompt`)
- Test: `test/prune.test.mjs`

**Interfaces:**
- Consumes: `boardView`, `boardSize`, `store.beginPrune/endPrune`, `store.saveVersion`, `agent.prune`.
- Produces:
  - `new Pruner({ store, agent })`
  - `pruner.available() -> boolean` (`agent.found`).
  - `pruner.run({ guidance = '', timeoutMs, signal }) -> Promise<{ ok, before, after }>`. In order:
    1. Save the version.
    2. Note `before = boardSize(store)`.
    3. `beginPrune()`.
    4. `agent.prune(prunePrompt(store, guidance), { systemPrompt: PRUNE_SYSTEM_PROMPT, timeoutMs, signal })`.
    5. `endPrune()`, in a `finally`.
    6. Note `after = boardSize(store)`.
    7. Post the summary as `'claude'` with `answers: []`.
  - `prunePrompt(store, guidance) -> string`: the whole `boardView(store, { fullNotes: true })` as JSON, the guidance if any, and the ask to prune it now.

**`PRUNE_SYSTEM_PROMPT`** is exact copy, from the spec's rules:

```
You are pruning a shared idea board that has grown too big for its collaborators to read. Make it smaller without losing a single decision. The whole board is in the prompt; change it with the board tools.

In this order:
1. Delete exact duplicates.
2. Merge restatements into one place. The settled version wins: usually the Brief, or a ticked entry. Merge into the item that already exists rather than adding a new one, so whoever started the idea keeps the credit.
3. Delete working copies whose content now lives somewhere settled, and flowchart cards still marked "idea" that are covered elsewhere or went nowhere.
4. Shorten labels, entry text, notes and Brief sections only where the meaning, the numbers and the reasons all survive. If something can't be shorter without losing context, leave it.

Law (the server refuses these, so don't try):
- Entries without a checkbox are plain bullets: never change or delete them. You may move them to another group. If something contradicts a plain bullet, the bullet is right; cut the other thing.
- Never add an entry without a checkbox, or take the checkbox off one.
- Struck-through (ruled-out) entries, the ruled-out list, accepted flowchart cards (and arrows between two accepted cards), pictures and the chat stay as they are. You may shorten a picture's caption, and add to the ruled-out list with rule_out.

When you are done, reply with a short summary for the chat: what you merged, what you cut and what you shortened, in a few lines.
```

**Summary post:** `${text}\n\nBoard size: ${before.toLocaleString('en-US')} → ${after.toLocaleString('en-US')} characters.`
- When the pass failed or was cut short, `text` is `Pruning was cut short (${error}). What it changed is kept; undo it from History.`
- With no reply text, `text` is `Pruned the board.`

- [ ] **Step 1: Write the failing tests.** Use a fake agent whose `prune` calls `store.apply` as `'claude'` and returns text.

  - `a failed or stopped pass still ends the prune and says so`. The fake returns `{ ok: false, error: 'stopped' }` (or throws). Afterwards `store.pruning === false`, and the post starts with `Pruning was cut short (stopped).`

- [ ] **Step 3: Implement** `Pruner` and `prunePrompt`. Build the version name from local time, like the page's `defaultVersionName` in `web/src/components/TopBar.svelte`.

### Task 5: The run decides when a pass happens

- Consumes: `Pruner`, `boardSize`, `PRUNE_THRESHOLD`, `PRUNE_REGROW`.
- Produces:
  - `new ColabRun({ ..., pruner = null })`.
  - `run.prune({ guidance }) -> { ok: true } | { error: string }`:
    - **Idle:** it waits for `settled()` (answers in flight), then runs the pass now.
    - **During a run:** it queues the pass for the end of the current round.
    - It refuses with `A prune is already going.` when one runs or is queued.

  - `status.pruning: boolean`, true while a pass runs.
  - While a pass runs, `status.connections.claude` is `{ state: 'thinking', activity: 'pruning the board' }`. Register the pass in `#busy` under `'claude'` with its own `AbortController`, as `#claudeTurn` does.
  - `run.stop()` also aborts a pass, whether idle or during a run, and a stop during a run ends the run after the pass.
  - `answer(id)` waits for a pass in flight before it starts its answer.
  - `startError()` returns `Wait for the prune to finish.` while a pass runs.
